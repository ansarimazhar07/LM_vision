### Executive Summary

Phase 9 establishes the definitive legal and technical bridge from a finalized inspection (`status === 'DECIDED'`) to a reproducible, tamper-evident **Inspection Report & Evidence Package**. 

LM-Vision operates strictly downstream of the GSR 202(E) compliance rule engine: the report generator consumes structured, verified data records and never prompts Gemini or any AI provider to formulate or modify statutory conclusions.

### Key Architectural Invariants & User Directives

#### 1. Presentation & Wording
- **Non-Governmental Designation**: The report and UI explicitly disclaim government-issued status unless formally designated by legal authorities.
  - UI Header: `🔒 FINALIZED INSPECTION REPORT / Generated by LM-Vision`
  - Decision Heading: `Inspector Final Decision` (strictly avoiding misleading titles like "Official Determination").
  - Statutory Advisory: Clearly states that LM-Vision is an AI-assisted regulatory verification software platform.

#### 2. Strict Dual Hash Semantics
- **`contentHash` (SHA-256)**:
  - Computed on the canonical inspection and report content payload.
  - Normalizes object key ordering (`canonicalStringify`).
  - Strips run-volatile and self-referential fields (`generatedAt`, `contentHash`, `reportHash`, `digitalSignature`, `status`).
  - Ensures identical byte-for-byte hashes across runs regardless of when or where the report is rendered.
- **`reportHash` (SHA-256)**:
  - Computed on the serialized canonical report envelope (including `contentHash`, `reportId`, and structural metadata, excluding only `reportHash` and `digitalSignature`).
  - Serves as the primary document integrity verification seal.

#### 3. Forensic Image & Evidence Integrity
- Original evidence images retain their own distinct SHA-256 hash (`Original Evidence SHA-256: <hash>`).
- Embedded thumbnails in HTML and PDF are explicitly labeled: `Thumbnail derived from Evidence ID: <id>`.
- Preserves full chain of custody without conflating derived compressed thumbnails with original high-resolution evidence.

#### 4. Finalization Gating
- Final reports can **ONLY** be generated when `inspection.status === 'DECIDED'`.
- Any attempt to generate a final report for an un-finalized inspection (`isDraftPreview: false`) is rejected by both `assembleInspectionReport()` and the server endpoint `POST /api/v1/reports/generate` with HTTP 400.
- Non-finalized inspections produce a clearly watermarked `DRAFT / PREVIEW` report with version `0.1.0-draft`.

#### 5. Cross-Platform Deterministic Hashing
- Implemented in pure TypeScript in `packages/rules/src/reporting/cryptoHasher.ts` with **zero Node.js standard library imports** (`crypto`, `fs`, `buffer`).
- Runs identically in Node.js, Web, and React Native / Hermes (Android & iOS), guaranteeing identical hash calculation with zero bundler breakage.

#### 6. Offline-First Mobile Experience
- **Offline**:
  - Inspectors can view the finalized inspection record, complete GSR 202(E) assessments, side-by-side human corrections, and forensic evidence appendix.
  - Canonical structured JSON export and local cryptographic hash verification are 100% functional offline.
- **Online**:
  - High-fidelity multi-page A4 PDF generation via `pdfkit` on the AI Engine backend (`POST /api/v1/reports/pdf`).
  - Private Supabase storage upload adhering to `<inspection_id>/report-<uuid>.<format>`.
